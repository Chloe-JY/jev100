# Candidate pipeline and files

## Input

```json
{
  "goal": "Find reusable open-source tools for an offline meeting assistant",
  "candidateType": "repository",
  "mustHave": ["offline transcription", "named action item owner"],
  "mustNot": ["required cloud inference"],
  "niceToHave": ["Chinese language support"],
  "reuseIntent": "deploy or adapt"
}
```

Source routing asks Jev first which of nine candidate categories fits, then which available catalog entry in that category is the best primary source. The included implementation is [`../scripts/route.mjs`](../scripts/route.mjs). Multi-source requests can choose multiple lanes; a single highest score must not hide a second required candidate type.

## Retrieval contract

The LLM plans several distinct search queries and calls a real tool or API. An adapter returns records in the form:

```json
{
  "source": "github",
  "nativeId": "owner/repo",
  "title": "owner/repo",
  "url": "https://github.com/owner/repo",
  "retrievedAt": "2026-09-27T00:00:00Z",
  "evidence": [{ "field": "offline", "text": "...", "url": "https://...", "location": "README / Features" }],
  "missing": ["license", "runtime test"]
}
```

Canonical URL/native ID must come from the source response. Remove duplicates and near-identical forks, track each query and pagination result, and stop at 100 distinct items or a documented source limit. Report a shortfall instead of fabricating records. Keep the original source response or a stable excerpt for audit.

## Jev scoring and Top 5

Use the same ordered 0–3 evidence scale for each candidate: 0 no support/contradiction, 1 adjacent/fragmentary, 2 mostly supported with a material gap, 3 explicit match. Questions are goal-specific; the stable dimensions are task fit, constraints, output/integration and ability to act. Ask each repository independently using the same goal, rubric and evidence. Hard constraints have `supported`, `contradicted` or `unknown` statuses outside the weighted score. A contradicted must-have is excluded from the eligible Top 5. An unknown goes to a separate verification queue.

For each shortlisted item, show component scores, one linked supporting or contradicting excerpt per critical dimension, and one next check: e.g. install offline, reproduce a paper, verify company filing, confirm a vacancy is still open. A textual explanation may be generated by an LLM only after evidence and scores are fixed; label it as a synthesis.

## Final deliverable structure

- `SKILL.md`: agent workflow and boundaries.
- `references/sources.json`: 100 candidate free-access sources, three gated reference sites, one optional metered aggregator.
- `references/setup.md`: Jev and optional Search1API setup, access states and deployment guidance.
- `references/pipeline.md`: input/record/output contracts and retrieval/scoring workflow.
- `references/evaluation.md`: statistical validation and benchmark interpretation.
- `scripts/route.mjs`: self-contained two-stage Jev source router.
- `scripts/doctor.mjs`: offline catalog and environment check.
- `scripts/github-fetch.mjs`: working GitHub Search API adapter that saves up to 100 real repositories with README excerpts. Queries are planned by the agent from the user's goal. `GITHUB_TOKEN` is optional for higher GitHub API limits.
- `scripts/rank-jev.mjs`: independently scores each saved candidate using Jev, retains per-item answers and eligibility, then exports the eligible Top 5. Requires `AI_GATEWAY_API_KEY`.
- `scripts/company-match.mjs`: separate six-dimension business-structure similarity ranking for dated company facts.
- `references/company-matching.md`: company data contract, scoring and evidence boundaries.
- `scripts/itjuzi-mcp.mjs`: authenticated MCP client and tool-result adapter; requires `@modelcontextprotocol/client` and `ITJUZI_MCP_API_KEY`.
- `scripts/itjuzi-vertical.mjs` and `scripts/itjuzi-demo.mjs`: small live embodied-AI tag → company → profile → product-score demonstration; does not create the 100-company historical corpus.
- `package.json`: official MCP client dependency for standalone use of the IT桔子 scripts.
- `README.md`, `package-lock.json` and `.gitignore`: standalone installation and GitHub packaging.

The local demo UI and prior GitHub benchmark remain in the sibling `StartupMirror` application; they are examples, not prerequisites for running the skill's GitHub pipeline. Other catalog sources still need individual live adapters.
